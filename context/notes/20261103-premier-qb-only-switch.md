# Premier "create in QuickBooks only" switch for inspections (Nov 3 2026) — PR into main, head `feat/premier-qb-only-switch`, merged: no
## CURRENT
**Why (Brett, Nov 3):** "switch premier to create in qb never email, but make sure this is only for inspections. we may do other work for them."
**Scope is inspections only by construction:** `Insp_Customers.Invoice_Delivery` / `Billing_Mode` live on the inspection-partner row and are read only by the inspection billing code (insbPlan / insbDeliver / insbQueue / fiBilling). Premier's regular Hub work orders bill through Owners/Work_Orders and never read them.
**Built:** (1) a switch on the customer edit screen (`inspect.html`, `ce-qo`): "Create the invoice in QuickBooks only. Never email it. Inspections only." It saves `Invoice_Delivery='qb_only'` through the existing `/insp/billing/customer-config`. Until now there was no way to set it from any screen. (2) Booking page: turning on `Billing_Mode='wo'` would have made Josiah's booking page REQUIRE a work order number, but the AppFolio WO and the booking arrive in either order. For a `qb_only` customer the field is now optional ("add it if you have it"); a number that is typed must still be valid; other billed customers still require it (`inspBookingWoInput`, `ask_wo` on `/insp-book/info`). Billing later refuses a booking that still has no WO. Tests: `test/insp-book-wo-optional.test.mjs` (13 checks).
**State of Premier's row before this:** `Billing_Mode`, `Bill_To_*`, `QBO_Customer_ID`, `Invoice_Delivery` all blank. Hub Owner 25 (Premier) has QBO customer 488; the inspection customer finds-or-creates its QuickBooks customer by name on first invoice, and the billing preview shows "linked / unknown" before anything is created.
**NOT done:** nothing is switched on yet (needs this merged, then Brett ticks "Bill automatically by work order" + the new switch and saves). No QuickBooks record created, no email sent.
