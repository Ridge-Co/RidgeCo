What was wrong: `/sms-inbound` is public and `handleInboundSMS` acted on the `From` / `Body` of any request. Anyone who knew a vendor's mobile number could POST `From=<number>&Body=NO` and decline + unassign that vendor's newest Assigned job (or `YES` to accept it). Confirmed on staging (version 2026-10-30.01-delivery-cotenants-keep-yes+202611162112.0a01b155): an unsigned POST from a made-up number was answered 200 with the normal "could not find your vendor record" reply.
What is built: `smsInboundSignatureGate` runs first in `handleInboundSMS`. It checks `X-Twilio-Signature` = base64(HMAC-SHA1(key = Worker secret `TWILIO_AUTH`, the account's primary Auth Token; message = full request URL + every POST field name+value, sorted by name, no separators)), per twilio.com/docs/usage/security (read Nov 16 2026). Switch: Config `SMS_INBOUND_SIGNATURE_MODE`; missing / anything else = LOG ONLY (nothing refused, P2 failure-ledger row "WOULD HAVE BEEN REFUSED" or "NOT CHECKED"), `enforce` = HTTP 403 (P2 row "REFUSED"); `enforce` with no secret = everything refused, P1 row. Ledger rows (`Where` = `inbound_text_signature`) are rate limited to 3 per 10 minutes per instance with a carried count; the switch is cached 60 s per instance; rows hold last-4 of the number only, never the text or the secret. If Config cannot be read, a request that failed the check gets 503.

**[FL-20261116-sms-inbound-signature]** `/sms-inbound` verifies `X-Twilio-Signature`. Regression rules: (1) the signature gate stays the FIRST thing `handleInboundSMS` does, before any sheet read keyed on `From` (a test pins the order). (2) The key is `env.TWILIO_AUTH` = the account Auth Token; never the API key secret, never a value in code. (3) The signed URL is `request.url` exactly as received (query string included); do not rebuild or re-encode it. (4) Only the exact word `enforce` (any case, trimmed) enforces; a missing or unreadable switch must never cause a request that failed the check to be handled as if it passed in enforce mode (unreadable = 503). (5) `enforce` with no secret refuses everything, loudly (P1). (6) Ledger rows stay rate limited and never carry a full phone number, message text or secret. (7) Any new public webhook from Twilio (voice, status callbacks) should use `twilioSignatureCheck` too. Tests: `test/sms-inbound-signature.test.mjs`.
