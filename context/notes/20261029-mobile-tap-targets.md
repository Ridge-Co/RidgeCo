## MOBILE TAP TARGETS + WIDE TABLES (Oct 29, 2026, branch `feat/mobile-tap-targets-oct29`, HTML only, Ops_Build_Queue #111) [FL-20261029-mobile-tap-targets]
**What.** Completes the open half of HUB_UX 3.3 after the 16px-input fix (PR #198 / #96). New `<style id="mobile-tap-targets">` block, placed right after `mobile-input-font`, in all 40 pages that carry that block (the 39 portals/tools plus `shop/index.html`). Same gate as #96: `@media (hover:none) and (pointer:coarse)`, so a mouse (narrow or wide) sees no change. Rules: `button`, `input[type=button|submit]`, `select`, `summary`, `.btn`, `.btn-sm`, `.filter-btn` and the `#rc-navbar` links get `min-height:44px !important`; buttons, `.btn`, `.btn-sm`, `.filter-btn` and navbar links also get `min-width:44px !important` (`!important` because pages have rules like `.btn.small{min-height:34px}`); `.modal-close` (was ~19px, `font-size:1.2rem`) is 44px with a 1.6rem glyph and negative margins so modal headers do not grow (the old rule at index.html ~193 is untouched); `div.tab` (owner, vendor, receipt-reconciler, Hub shopping tabs) gets min 44x44 and is centred with `display:flex`; `.table-wrap` is defined in every block. Heights are minimums, never fixed.
**Hub header (index.html only, a design change Brett should look at).** The 17 nav buttons wrapped into a sticky block about 320px tall at 360px wide already; 44px rows would have made it about 485px. So on a touch phone (`max-width:600px`) the nav is now ONE swipeable row of 44px buttons and the header is about 70px tall. Items off-screen need a swipe; the active item is not scrolled into view. To undo: delete the second `@media` block in index.html's `mobile-tap-targets` style.
**Wide tables.** Five raw static tables wrapped in the existing `.table-wrap` pattern (clickup-importer x2, data-importer x2, patch-importer x1; markup only, ids untouched). Tables built by JS get a CSS-only fallback on the tool pages: `*:has(> table){overflow-x:auto}` (parent of a table scrolls), plus `#key-search-table{overflow-x:auto}` on the Hub (its Keys search table was the one JS table with 8 columns and no wrapper). Index.html tables at 1622/1642 sit inside `overflow-y:auto` boxes (which compute `overflow-x:auto`) and the WO detail table at 2745 is two columns, so they were left alone. **Found while auditing:** `patch-importer`, `qb-email-backfill`, `qb-invoice-email-backfill`, `wo-bulk-fix` rows (`.row input{flex:1}`) pushed the page to 415px wide at a 360px phone because the 16px font from #96 made the input's own width bigger than the row (fixed with `.row>input{min-width:0}`); `clickup-importer` (492px) and `data-importer` (456px) were their unwrapped tables.
**Documented exceptions.** Checkboxes/radios/file inputs (resizing breaks the forms; file inputs stay out of labels, rules 132/134), plain text links inside a sentence (`shop/index.html` "Text 443-..." footer link), and the 12 row checkboxes on the one-time `data-importer` page.
**Not changed.** No JS, no `worker.js`, no `BUILD_VERSION`, no EN/ES text, the #96 input-font blocks, `body{overflow-x:hidden}` (rule 120), the Tools & Log 44px rules (min-height is a floor, so nothing is double-sized). `read-meter.html` also has a raw table but carries neither mobile block; left out.
**Verified.** `test/manual-verify-small-fixes-ui.mjs` grew from 70 to 122 checks (all pass; the new ones fail 47 ways on main, so they test something). They cover: block present on all 40 pages after the #96 block with the same gate; at 360 and 390 every real control and every probe (`.modal-close`, `.btn-sm`, `.btn`, inline x, select, `input[type=button]`, `.filter-btn`, `div.tab`) is at least 44px and no page scrolls sideways; the Hub signed in (mocked) across 8 pages; tenant and owner signed in; closed modals and inactive screens stay `display:none`; tables scroll in their own wrapper; a 700px mouse window and 1280px desktop are unchanged. Byte check: every one of the 40 pages equals main plus the style block (plus the wrappers on 3). Inline-script `node --check` on 73 scripts clean; full unit suite 292/292, same as main.
**Regression rule.** Any new user-facing page must carry BOTH `mobile-input-font` and `mobile-tap-targets`, and the Hub nav stays a single row on phones. **Brett to check on the S23 Ultra before merge:** see the PR body.
