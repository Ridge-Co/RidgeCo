## FEATURE_LOG entry

**231. Appointment Shift: one tool to move Brett's own appointments, plus the new inspection length rule (Oct 23 2026, branch `feat/appointment-shift-oct23`; worker.js, shift.html, inspect-change.html, index.html tile, inspect-book.html, HubScheduler.gs, tests; Brett: "running late, shift the rest of today", ShowMojo style, with a checkbox per item).**
**What it is:** admin page `shift.html` (dashboard tile "Shift Appointments") backed by `POST /shift/preview` (writes nothing) and `POST /shift/apply`. Two modes: **Re-lay the day** (first start of the day unchanged; each later start = previous end + the stored drive minutes, rounded UP to the next quarter hour) and **Running late** (+15/+30/+45/custom; moves checked items starting from now). Every item has a checkbox and editable start/end; a plain-words list says exactly what Apply will do. An adapter registry decides what can move: **inspection** (propose, then partner approves), **wo_window** (Brett's OWN In_House work-order windows with two clock times, applied through `scheduleWO` with read-back, tenant notice through the normal path), **delivery** (LOCKED: the store sets the window), **vendor** (reserved, shown as locked "not built yet", pinned in BACKLOG).
**Duration rule (new bookings only):** 30 min per unit + 30 min per BUILDING, rounded up to 5, floor 30 (1u=60, 4u/1b=150, 2b x 2u=180). `inspDurationMin` in worker.js and `durMin` in inspect-book.html. Existing bookings change length only through a shift.
**Inspection flow (propose, then approve):** Apply saves `Change_Status=proposed` with `Proposed_Start_ISO/End_ISO/Duration_Min`, `Change_Token`, `Change_Batch` (new Insp_Bookings columns via `ensureColumns`), the booking stays at its OLD time, and ONE editable email goes to `josiah.speed@ppmillc.com` (Config `INSP_SHIFT_NOTICE_EMAIL` overrides) with an Approve link per inspection, a Reschedule link per inspection and an Approve-all link. The email never mentions tenants. Public tokened page `inspect-change.html` (`/insp-change/info|approve|reschedule`, in PUBLIC_PATHS, self-verifying). Approve = conflict re-check (sheet incl. other proposals, Brett's calendar, cleaning guard), decision recorded, sheet row written with read-back, calendar PATCH verified, key pickup reconciled for old and new day, invite ICS REQUEST with `SEQUENCE` from `Ics_Seq`+1 (same UID so it replaces the old entry), THEN tenant text (if enabled) and the Brett notice, then `applied`. Reschedule = `reschedule_requested`, Brett alerted by email AND text, partner sent to the existing manage page (cancel and rebook; v1).
**While a proposal waits, BOTH the old and the proposed window are taken** (slot picker `inspAvailability`, `inspBookingDecide`, the shift engine).
**Tenant notice:** flag `Insp_Customers.Notify_Tenants` (default FALSE; Premier FALSE). When TRUE, tenants are texted only through `smsGatedSend` (the existing pipeline: switches, opt-out, quiet hours, test mode). A number that exists only in the inspection roster and is not a Hub tenant is NOT texted, and that gap is reported (ledger + result warning + preview), never skipped quietly.
**No silent failures:** any failed step sets `Change_Status=failed` with the reason, writes Ops_Telemetry Success=FALSE, alerts Brett loudly, shows the partner "we will follow up", and NOTHING downstream goes out after a failed write. If the proposal email fails, the proposals are withdrawn (read back) and Brett alerted. A stale plan id (data moved since preview) is a 409 and nothing is written; an overlap with a booking that is not part of the shift is a 409 and nothing is written. Re-applying the same plan is idempotent (no second email). **Apply anyway** (`/shift/force-apply`) commits an unanswered or failed proposal and RECORDS the override in `Change_Note`.
**Reminders (NO cron):** SCHED_JOBS `insp_shift_reminders` (interval 59 min) plus the JOBS row in `HubScheduler.gs`: flags a proposal unanswered 12 h (Config `INSP_SHIFT_REMIND_HOURS`), URGENT with a text within 24 h of the visit, closes proposals whose visit time passed, marks an approval stuck 15 min as failed. Brett must paste the JOBS table into Apps Script for it to run (the Hub side is deployed with the Worker).
**Regression rules:** never let a proposal change the booking's Start/End before approval; never send the partner invite or any tenant text before the sheet row and calendar are confirmed; the ICS SEQUENCE must only go up; the shift block never builds its own SMS sender; delivery windows stay locked; staging `hubTestWriteAllowed` allows shift writes only for TEST- customers/WOs.
**Known gaps (stated, not hidden):** vendor shifting is not built (locked rows say so); wo_window is only for In_House vendors with two-clock-time windows ("Within 1 hour" / "All Day" are locked); reschedule v1 sends the partner to the manage page; tenant text works only for Hub tenants.
**Verified:** new `test/appointment-shift.test.mjs` (exact Premier times for the six: Tue 11:00-12:00 / 12:15-1:15 / 1:30-2:30, Wed 10:30-11:30 / 12:15-1:15 / 2:00-3:00; DST fall-back Sun Nov 1 2026; locked items; propose/approve; idempotency; failure injection at every step; SMS routing; reminders; source guards). Registry and count tests updated (`scheduler`, `no-cron-anywhere`, `devlog-tools`, `insp-booking`).
