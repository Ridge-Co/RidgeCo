# Premier inspection billing, step 1 (WO number, "Invoiced" mode, paid tracking) — Nov 2 2026 — PR #496 into main, head `feat/insp-invoiced-wo-number` (cut from main tip + merge of the Oct 22 billing build), merged: no
## CURRENT
**Why (Brett, Nov 2):** Premier Property Management uses AppFolio (no API). Each inspection is invoiced by hand there ($95/inspection line, PDF uploaded, note with the report link, Work Done). Brett wants: the WO number on the report and invoice "so there is always a reference"; an **Invoiced** mark that creates the QuickBooks invoice but does NOT send it; payment tracking (Premier pays by ACH) so a subcontractor can be paid; a vendor bill for the assigned vendor (none when Brett did it himself); and, later, the AppFolio accept + submit automated with a "needs manual entry" flag.

**Built in this PR (step 1 only):**
- Revived the Oct 22 inspection-billing build (INSB block, Needs-billing card, Complete & bill sheet, booking `WO_Number`) on current `main` by a server-side merge; its context-file edits were reverted so only this note rides along.
- **WO number on the public report**: `/fi/report` adds `wo_number` (looked up from `Insp_Bookings` by `Inspection_ID`; a failed lookup is logged to Ops_Telemetry as `insp-billing/report_wo` and flagged `wo_lookup_failed`). `inspection-report.html` prints "Work order" in the header (and so in the PDF).
- **Invoiced mode**: new `Insp_Customers.Invoice_Delivery` (`''` = email our invoice, `'qb_only'` = create it in QuickBooks, never email it). `insbPlan` reports `qb_only` + a warning, `insbRecipients` needs no email address for it, `insbDeliver` skips our invoice's email (status stays `invoiced`), the Needs-billing queue does not nag about it. Set via `/insp/billing/customer-config { Invoice_Delivery }`. The owner-facing invoice B is unchanged (held until markup).
- **Paid tracking**: new booking columns `Paid_At`, `Paid_Source` (`quickbooks`|`manual`), `Paid_Note`. `POST /insp/billing/check-paid {id?}` reads the QuickBooks invoice balance and stamps paid at balance 0 (part-payments are not paid; no id = sweep up to 40; failures -> 502 + `errors` + Ops_Telemetry). `POST /insp/billing/mark-paid {id, confirm:true, paid_on?, note?, undo?}` is the manual version.
- **Field Inspection Review screen**: new "Work order & billing" card (`GET /fi/billing?id=`): shows the WO (or a warning + field to add it), the customer, a **Mark invoiced** / Complete & bill button (preview -> confirm, sends `expected_cents`), the Invoiced/Paid chips, **Check if paid**, **Mark paid** (two taps) and Undo.
- Tests: `test/insp-billing.test.mjs` 401 checks (new sections 25-28), `test/fi-billing-card.test.mjs` 38 checks. Full suite result is in the PR body.

**NOT built / not verified:** staging smoke test status is in the PR body. No real QuickBooks record was created and no email sent by this work. **Not done yet:** vendor bill for subcontracted inspections (pay rule unknown), AppFolio email capture + WO matching (step 2), headless-browser accept/submit (steps 3-4), what AppFolio sends when Premier pays by ACH (unknown; check-paid reads QuickBooks, so it needs the deposit booked there). Hub work-order integration is deliberately not entangled with Who To Pay / Invoice_Review.

**Decision (Brett, Nov 2 evening):** merge #496. Subcontractor pay for an inspection starts at **$40 per inspection** for the vendor (his words: "don't know yet but going to start at $40"); it may change, so keep it a setting when the vendor bill is built, not a hard-coded number.

**Guardrails kept:** merge to `main` is Brett's call; WO 43945-1 (Gilmor) is not completed or billed without his explicit word; nothing is created in real QuickBooks without his say-so.

## FEATURE_LOG
**[FL-20261102-insp-invoiced-wo]** (1) The public report payload carries `wo_number` from the booking (by `Inspection_ID`); never put other booking fields (contact, notes) on the public report. (2) `Insp_Customers.Invoice_Delivery='qb_only'` means "create in QuickBooks, never email our invoice": `insbDeliver` must keep `needA=false` for it and `insbQueue` must keep excluding it from `needs_attention`; the owner invoice B is independent. (3) Paid is only ever stamped by a verified write after QuickBooks shows balance 0 on a non-staged invoice, or by an explicit confirmed manual mark; a QuickBooks error stamps nothing and is reported + logged. (4) `/insp/billing/check-paid` with no id reads every real invoice, so the staging test token is refused for it. (5) The FI Review billing card never bills without a preview and sends `expected_cents`. Tests: `test/insp-billing.test.mjs`, `test/fi-billing-card.test.mjs`.
