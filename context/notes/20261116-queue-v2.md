## FEATURE_LOG
**[FL-20261116-queue-v2]** Queue v2. One lifecycle column (`Stage`) beside Status / Build_State on `Ops_Build_Queue`; narrow report-back route `POST /ops-queue-stage`; scheduler job `queue_sync`; deploy check; risk guard; proposals.html board. Regression rules:
1. **Status and Build_State are always written in step with Stage** (`queueStagePlan`, `queueSyncStageFields`, `queueDeployStep`). A stored Stage only counts while the two old columns still agree with it (`QUEUE_STAGE_FAMILY`); never read the Stage cell directly, use `queueStageOf`.
2. **Never backfill Stage.** Blank means "work it out". `GET /ops-queue` writes nothing.
3. **`/ops-queue-stage` rejects unknown fields and unknown ids.** Adding a settable field means adding it to `QUEUE_STAGE_FIELDS` (or the Brett-only list) and a test both ways.
4. **A token can never approve, drop, snooze, send to review, mark SAFE, or unblock a row blocked on Brett.** Identity comes from the credential (`queueActorOf`), never the body.
5. **Merged / live / done need a PR GitHub confirms is merged** for any token, and for Brett on a GATED row. GitHub unreachable = not marked.
6. **The risk guard only tightens.** A SAFE label never overrides a rule hit; nothing to read, a cut-off file list, or a code file with no diff is GATED.
7. **No cron.** `queue_sync` is a SCHED_JOBS entry plus a JOBS row. The tick treats GitHub 403 / 429 as `rate_limited` (retried), every other error as a job error. The daily run stays strict.
8. **The `QUEUE_RISK_RULES` text must stay bracket-balanced** (write `\x28`, not an escaped round bracket): several tests read worker.js constants by counting brackets.
9. **proposals.html:** no fixed-pixel page column, chips wrap, no text under 13px, Approve defaults to "Decide for me", every write goes through `guarded()` (button disabled before any await, restored on success and failure), every fetch failure is shown with Try again, no Start Build / routine code.
Tests: `test/queue-v2.test.mjs`, `test/manual-verify-queue-v2-ui.mjs`.
