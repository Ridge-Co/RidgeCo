## Rule 231 (FEATURE_LOG)
**231. Properties page: per-property switches, customer "apply to all", duplicate and merge, detail tabs, and the proposal screen says when the owner text is held (Oct 24 2026; Brett: texts to tenants and owners must be settable separately per property; a way to fix duplicate properties such as 411 W 23rd St (93) vs 411 West 23rd St (94); a property detail view; and "the proposal screen should tell me when the owner text will not send").**
**Cause:** the only text switch on a property was `SMS_Enabled`, edited by hand in the sheet, and it covered tenants AND owners together. The proposal screen promised "the owner also gets a short text" even when `smsGateDecision` would block it (Property OFF, Customer OFF), so a held text was silent. There was no way to mark or merge a duplicate property; the old `/admin/merge-property` skips inactive rows and has an incomplete reference list.
**Fix:** (1) One registry `PROPERTY_TOGGLES` (Active, Tenant WO submission, SMS master, SMS to tenants, SMS to owner, SMS to vendors, Owner emails). New columns `SMS_Tenants_Enabled`, `SMS_Owners_Enabled`, `SMS_Vendors_Enabled`, `Owner_Email_Enabled` blank = ON, so nothing flips on deploy; created with `ensureColumns` the first time a switch is changed. `smsGateDecision` takes optional `propertyTenantsOn/OwnersOn/VendorsOn` flags tested with `=== false`; absent flags behave byte-for-byte as before (512-combination oracle). Every call site spreads `smsPropertyGateFlags(property)`. New held reasons show in `Gate_Snapshot` ("Property tenant texts OFF", "Property owner texts OFF", "Property vendor texts OFF"). `addonEmailGate` checks `propertyOwnerEmailOn` AFTER its existing outcomes (none of those changed). Vendor texts resolve the property from `opts.property`, `opts.property_id`, or the work order; a failed lookup is reported (P2) and the text still goes (fails open, visibly). (2) **Terminology as built:** Customer = an `Owners` row (via `Properties.Owner_ID`; today's `Owners.SMS_Enabled` is the "Customer OFF" gate); Owner = the person (the row's contact plus `Owner_Users` logins, which have no SMS switch). "Apply to all of this customer's properties" is an explicit, previewed write of the per-property column with a Leave-out checklist: `POST /owner/property-toggle-preview` then `/owner/property-toggle-apply` (needs the preview token, confirm:true, read-back per property, refuses if data changed since preview). No live inheritance; later properties are not touched. (3) Duplicates: Mark as duplicate (`Duplicate_Of`, `Duplicate_Marked_Date`, Active FALSE; restorable; nothing deleted or moved). Merge into another property: side-by-side pick only where both sides hold different non-empty values, a non-empty value is auto-taken over an empty one, `Owner_ID`/`QBO_Customer_ID` that differ is a hard block; every reference re-pointed from `PROPERTY_REF_REGISTRY` (26 columns incl. comma lists) found by header on the live sheet, inactive rows included; an unrecognised property-looking column BLOCKS the merge; per-tab counts before confirm; after the move every tab is re-read and leftovers are counted and reported; source marked last. (4) Detail view in index.html: tap a property row, tabs Settings / Info (every column, grouped; key, lockbox and door codes hidden behind a Show button, admin screen only, never in a vendor-facing endpoint) / Units (adds `HVAC_Filter_Size`, `HVAC_Change_Interval`) / Cleanup; list rows get small badges and a Hidden/Duplicates view; lazy `GET /property/detail?id=`, no extra reads for the list; deep link `?property=ID&tab=settings`. (5) `GET /sms/gate-preview` (admin, read-only, `smsGatePreview` shares `smsGateDecision`) feeds scope-creator.html: before sending it says "The text will NOT send: ..." with a link to that property's Settings tab, the confirm box no longer promises a text that will not go, and after sending it shows the real outcome. Message Queue pending rows show the held reason with a Settings link. Manual Send still skips quiet hours (unchanged).
**Regression rule:** a new property switch must be added to `PROPERTY_TOGGLES` and wired into its send gate in the same change; a blank cell is ON for the new columns; never add an `smsGateDecision` caller without `smsPropertyGateFlags(property)`; never change existing `addonEmailGate` outcomes; "apply to all" never writes without a preview token and confirm; a merge must never delete, must refuse on an unknown reference column, and must verify by re-reading every tab; never show key/lockbox/door codes on a vendor-facing screen; the proposal screen must never promise an owner text without asking `/sms/gate-preview`.
**Known gaps:** vendor texts sent with no work order and no property (PIN texts, some direct sends) cannot be property-gated; the proposal EMAIL has no property gate; Goldszmidt (Owners 3 and 19, same Company) is two "customers", so apply-to-all covers one account at a time; the old `/admin/merge-property` is untouched; text that merely mentions an old address in free text is not rewritten by a merge; 93 into 94 was previewed in tests only and NOT executed; the new write routes are covered by `hubTestWriteAllowed` (TEST- records only) but were not exercised on the real staging Worker.
**Verified:** new `test/property-toggles.test.mjs` (2226 assertions incl. the 512-combination back-compat oracle, merge field plan, 26-column registry, forced Sheets write failures on toggle/apply/merge, vendor property lookup failure); harness stubs added to `_d16-support`, `fix-check`, `mq-save-and-cron-storm`, `str-cal-impersonate`, `vendor-additional-work`, `wo-combine`, `wo-duplicate`, `wo-split`; real-browser phone-width scripts `manual-verify-property-detail-ui` (40/40), `manual-verify-proposal-sms-hold-ui` (19/19), `manual-verify-mq-gate-link-ui` (8/8) with only the Worker mocked. Not verified against the real Worker or staging (see PR).
