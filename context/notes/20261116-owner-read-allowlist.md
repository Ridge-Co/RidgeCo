## FEATURE_LOG
**[FL-20261116-owner-read-allowlist]** An owner session's answers from `/owner-workorders`, `/owner-properties`, `/wo-audit` and `/attachments` are allow-listed. Regression rules: (1) never go back to spreading a sheet row (`...wo`, `...p`) into an owner-session answer; add the field to the matching `OWNER_*` list instead, on purpose. (2) An owner history line is shown only when its `Field` is in `OWNER_AUDIT_FIELDS`, or it is a message whose `Recipient_Type` is `owner` (never with the message body). (3) Owners see receipts, never bill / invoice / unknown-type attachment rows (Brett, Sep 16 2026). (4) A new GET route in `ROLE_SCOPES.owner` must be added to `COVERED_GET` in the test with its own check, or the test fails. (5) Every work-order field `owner.html` reads must be in `OWNER_WO_VIEW_FIELDS` (the test reads the page). (6) `getWOAudit` must not answer `[]` on an error. Tests: `test/owner-allowlist.test.mjs`.
Known and left as is (not internal cost data, named so nobody is surprised): `Notes` on the job is shown to owners by design and can hold a vendor's status note; a `Status` history line can show the internal status name "Pending Invoice" (the job list maps it to "Complete"); `/owner/get-billing` returns the owner's own `qbo_customer_id`.
